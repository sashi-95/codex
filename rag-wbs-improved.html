RAG戦略・WBS

Copilot 365 / Zendesk AI統合による継続学習システム構築

📊 1. 現状の課題と解決策

⚠️ 現状の課題

  • Zendesk問い合わせ対応の工数増大: エスカレーション発生時に、UC（ユーザーケア）が手動で返信を作成するため、多くの時間とリソースを消費
  • 知識の分散: 企業内のナレッジがSharePoint、Zendesk、メールなど複数の場所に散在し、統合的な活用が困難
  • 回答品質のばらつき: 担当者によって回答の質や一貫性に差が生じる
  • 学習の非効率性: 過去の成功事例や失敗事例が体系化されず、同じ問題を繰り返し解決する必要がある

✅ RAG + フィードバックによる解決策

参考: RAGとフィードバックを活用した継続学習する返信生成サービス

  • 自動返信生成: 過去の問い合わせデータと企業ナレッジをRAGで検索し、高品質な返信を自動生成
  • 継続的改善: 生成された回答に対するフィードバック（絵文字リアクション、コメント）を収集し、システムの品質を継続的に向上
  • 統合データ活用: SharePoint、Zendesk、社内DBを統合したRAG基盤により、全社の知識資産を有効活用
  • Copilot 365 / Zendesk AI統合: 既存のMicrosoft 365とZendesk環境にシームレスに統合

💾 2. データ資産の理解

📊 構造化データと非構造化データ

RAGシステムを構築するためには、企業内のデータを「構造化データ」と「非構造化データ」に分類し、それぞれの特性に応じた処理が必要です。

データ種類 データソース例 用途・特徴 RAGでの活用方法
構造化データ Snowflake、CRM、社内DB、Excel 顧客情報、取引履歴、売上データなど、表形式で整理されたデータ 検索結果の補足情報として活用。直接的な回答生成には非構造化データが主
非構造化データ SharePoint文書、Zendeskチケット、メール、PDF、Word、マニュアル 自然言語で書かれた文書、過去の問い合わせ履歴、ナレッジベース RAGの主要なデータソース。Embedding化してVector DBに保存し、意味検索に活用

🔗 自社データとRAGの統合

構造化データと非構造化データを統合的に活用することで、より正確で文脈に富んだ回答を生成できます。例えば、Zendeskの過去チケットから類似事例を検索し、Snowflakeの顧客情報を補足情報として追加することで、パーソナライズされた回答が可能になります。

各フェーズの詳細

📥 準備フェーズ

  • Zendeskから問い合わせと返信のペアデータを定期的にBigQueryに転送
  • SharePointのドキュメントを同期し、Vector DBに保存
  • ML.GENERATE_EMBEDDING関数を使用してテキストをベクトル化
  • ベクトル化されたデータをVector DBに保存（検索用インデックス構築）

🤖 返信生成フェーズ

  • Slack/TeamsからのWebhookで新規問い合わせを受信
  • VECTOR_SEARCH機能を使用して、新規問い合わせに類似する過去の問い合わせ・返信を検索
  • 検索結果（Good/Badフィードバック付き）をプロンプトに追加
  • Azure OpenAIまたはGeminiを使用して回答を生成
  • 生成された回答をSlack/Teamsに投稿
  • 生成された回答をBigQueryに保存・ベクトル化（次回検索に活用）

📈 フィードバック収集フェーズ

  • Slackの絵文字リアクション（👍/👎など）とコメントをWebhookで受信
  • フィードバックデータをBigQueryに保存
  • 次回の検索時に、Goodフィードバックの回答を優先的に参照
  • Badフィードバックの回答を分析し、改善点を学習

統合のメリット

  • 一元化された知識管理: SharePoint、Zendesk、社内DBの知識を1つのVector DBに統合し、全社で共有
  • シームレスな連携: Copilot 365とZendesk AIが同じ知識ベースを参照するため、回答の一貫性が向上
  • 権限管理の継承: 元のデータソース（SharePoint等）のアクセス権限をRAGシステムが継承し、セキュリティを維持
  • コスト効率: 共通基盤により、インフラコストと運用コストを削減

📋 5. WBS（Work Breakdown Structure）

📋 プロジェクトの主要フェーズ

RAGシステム構築を4つのフェーズに分解し、各フェーズの主要タスクを明確化します。

フェーズ1: 準備（Preparation）

  • 要件定義: ビジネス要件、技術要件、セキュリティ要件の明確化
  • データ棚卸し: 構造化/非構造化データの洗い出し、データ品質評価
  • 権限設計: データアクセス権限のマッピング、RAGシステムへの権限継承設計
  • 技術選定: Vector DB（BigQuery / Azure AI Search）、LLM（Azure OpenAI / Gemini）の選定
  • PoCスコープ定義: 対象データ、ユースケース、成功指標の設定

フェーズ2: 構築（Development）

  • Vector DB構築: BigQueryまたはAzure AI Searchのセットアップ、スキーマ設計
  • Embedding パイプライン開発: データ転送、チャンキング、ベクトル化の自動化
  • RAG API開発: FastAPIまたはAzure Functionsでの返信生成API実装
  • 検索ロジック実装: VECTOR_SEARCH機能の実装、類似度閾値の調整
  • プロンプトエンジニアリング: LLMへのプロンプト設計、Few-shot学習の実装

フェーズ3: 統合（Integration）

  • Zendesk連携: Zendesk API連携、Webhook設定、Zendesk AI統合
  • Copilot 365連携: Microsoft Graph API連携、SharePoint同期、Copilot拡張機能開発
  • Slack/Teams通知: 返信生成結果の通知機能、フィードバック収集機能
  • フィードバックループ実装: フィードバック収集API、学習データの自動更新
  • モニタリング・ロギング: システム監視、エラーハンドリング、パフォーマンス計測

フェーズ4: 運用・改善（Operations & Improvement）

  • PoC実施: 限定ユーザーでのテスト運用、フィードバック収集
  • 品質評価: 正答率、ハルシネーション発生率、ユーザー満足度の測定
  • 継続改善: フィードバックに基づくプロンプト調整、チャンキング戦略の最適化
  • 本番展開: 全社展開、スケーリング、コスト最適化
  • ドキュメント整備: 運用マニュアル、トラブルシューティングガイドの作成

🎯 7. PoC提案

🎯 PoCスコープ

対象データ

  • Zendesk: 過去6ヶ月の問い合わせチケットと返信（約1,000件）
  • SharePoint: カスタマーサポート関連のナレッジベース（FAQ、マニュアル等）
  • 構造化データ: 顧客基本情報（Snowflake）を補足情報として活用

ユースケース

  • 主要ユースケース: Zendeskチケットへの自動返信生成
  • 補助ユースケース: Copilot 365での社内ナレッジ検索
  • 対象ユーザー: カスタマーサポートチーム（10名程度）

📊 成功指標（KPI）

指標 目標値 測定方法
返信作成時間削減率 50%以上 生成前後の平均作成時間を比較
正答率 90%以上 専門家による回答品質評価
ハルシネーション発生率 5%以下 事実誤認の検出数 / 総生成数
ユーザー満足度 4.0/5.0以上 フィードバック絵文字の平均値
システム応答時間 5秒以内 問い合わせ受信から回答生成までの時間

🔄 フィードバック収集メカニズム

Zenn記事を参考にした継続学習システム:

  • Slack絵文字リアクション: 👍 (5点) / 👎 (1点) など、5段階評価でフィードバックを収集
  • コメントフィードバック: 具体的な改善点をコメントで収集
  • 自動学習: Goodフィードバック（4-5点）の回答を次回検索で優先参照
  • 改善サイクル: Badフィードバック（1-3点）の回答を分析し、プロンプトやチャンキング戦略を改善
