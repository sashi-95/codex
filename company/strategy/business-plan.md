# Business Plan — AIオートメーション会社 (1人創業)

最終更新: 2026-07-13 / ステータス: Phase 1 ドラフト
関連: [positioning.md](positioning.md) / [ideal-customer-profile.md](ideal-customer-profile.md) / [../services/service-catalog.md](../services/service-catalog.md) / [../../ROADMAP.md](../../ROADMAP.md)

## 1. ミッション

企業のバックオフィス・ERP・カスタマーサポート・レポーティング・定型業務を、
AIエージェント / 業務自動化 / API / RPA / ナレッジ検索で効率化する。
**コンサルティングではなく、実際に動く仕組みを14営業日以内に納品する。**

## 2. 事業の骨格

| 項目 | 内容 |
|---|---|
| 事業形態 | 1人会社 (創業者 = 営業/設計/実装/納品)。AIエージェント群を「社員」として活用 |
| 主力商品 | AI Backoffice Automation Sprint (7〜14営業日で1業務を自動化) |
| 収益の柱 | ①Assessment ②Sprint ③月額保守 (MRR) ④追加開発 |
| 長期方針 | 人月依存を減らし、テンプレート→エージェント→SaaSへ移行。企業価値10億円以上 |
| 拠点 | ニューヨーク (在米日系企業への近接性 + 日英バイリンガルを武器に) |

## 3. 市場と機会

- **一次市場**: 在米日系企業 (製造・商社・物流の現地法人)。SAP + 小規模バックオフィス
  チームという構成が典型で、本社標準システムを変えられないまま手作業が滞留している。
  日英バイリンガルで業務とERPの両方を理解する実装者は極端に少ない
- **二次市場**: 米国ミッドマーケットのSAP/Zendesk利用企業 (従業員100〜1,000人)
- **追い風**: AIエージェントへの投資意欲は高いが、企業は「PoCで止まる」ことに疲れている。
  「14日で動くものを固定価格で」は明確なアンチテーゼになる

## 4. 収益モデル

```
フェーズ1 (M1-6): プロジェクト収益で現金を作る
  Assessment $3,000 → Sprint $15,000/$25,000 → 保守 $3,000-10,000/月
  1案件の理想LTV: 15,000 + (5,000×12) = $75,000/年 (Assessment $3,000はSprint費に充当)

フェーズ2 (M7-12): MRR比率を上げる
  保守契約の標準化 (監視・改善枠・軽微変更をパッケージ化)
  同型ソリューションの複数社展開 (2社目以降は原価が下がり粗利が上がる)

フェーズ3 (Y2以降): プロダクト化
  再利用テンプレート → 設定ベースのエージェント製品 → SaaS
```

**価格原則**: 作業時間ではなく、削減工数 × 業務価値 × リスク低減 × 再利用性で決める
(詳細は [../services/pricing.md](../services/pricing.md))。

## 5. 12か月の財務目標 (§ROADMAP.mdと同期)

| 期間 | 売上目標 | MRR目標 | 主要マイルストーン |
|---|---|---|---|
| M1 | — | — | ポジショニング確定 / サイト公開 / 営業資産完成 / 見込み100社 / 商談10件 |
| M2-3 | 累計$30,000+ | 保守1件 | Assessment 3件 / Sprint 1-2件 |
| M4-6 | 月商$50,000 | $15,000 | テンプレート標準化 / 外部委託作業の分離 |
| M7-12 | 年商$500K-1Mランレート | $50,000 | 顧客10-20社 / SaaSプロトタイプ / 創業者非依存の体制 |

キャパシティ制約 (1人): 同時進行はSprint 2件 + Assessment 1件が上限。
それを超える需要は価格改定 or 開始時期調整 or 外部委託で吸収する。

## 6. 提供サービス (概要)

詳細は [../services/service-catalog.md](../services/service-catalog.md)。

1. **Automation Assessment** ($3,000) — 対象業務の選定・ROI試算・実行計画
2. **AI Automation Sprint** ($15,000) — 1業務を7〜14営業日で自動化し本番納品
3. **Enterprise Sprint** ($25,000) — SAP等の基幹系・承認フロー・監査要件を含む案件
4. **Monthly Support** ($3,000〜10,000/月) — 監視・保守・改善枠
5. **追加開発** — 固定価格 (原則) または時間単価

## 7. 競争優位 (要約)

1. **実装まで持つコンサルは少なく、業務が分かる実装者はさらに少ない**:
   SAP FI/S4HANA × Zendesk × Power Automate × Python × RAG を1人で跨げる
2. **日英バイリンガル + NY日系企業の業務経験**: 本社(日)と現地(英)の板挟み構造を理解
3. **納品済みテンプレート資産**: 本リポジトリのプロトタイプ群
   (マルチエージェント基盤 / Zendesk自律エージェント / SAP転記ランタイム / SAP GUI
   VBS+PAD) が初日から流用可能 = 14日納品の裏付け
4. **セキュリティ設計を最初から**: HITL承認・監査ログ・データ分離を標準装備
   ([../security/security-principles.md](../security/security-principles.md))

## 8. リスクと対処

| リスク | 対処 |
|---|---|
| 創業者が単一障害点 | 標準化されたrunbook・テンプレート・引き継ぎ資料を常に納品物と同時作成 |
| 大型案件への誘惑 (人月化) | 意思決定原則§11で拒否。Sprintの分割提案に変換する |
| PoC止まり顧客 | Assessmentで「本番化の意思とデータアクセス」を受注条件として確認 |
| スコープクリープ | SOWでスコープ外を明文化。変更は追加開発として見積 |
| 未収リスク | Sprint は50%前金。保守は前払い月額 |

## 9. 意思決定原則 (全ドキュメント共通)

迷ったら以下の順で判断する:

1. 顧客が実際に金を払うか
2. 14日以内に納品できるか
3. 定量的なROIを示せるか
4. 別の顧客へ再利用できるか
5. 月額契約につながるか
6. 創業者の時間を増やさず売上を増やせるか
7. セキュリティと信頼性を維持できるか

デモ・ポートフォリオ・技術的自己満足は作らない。すべての活動は
**受注 / 納品 / 継続契約 / 再利用可能なIP** のいずれかに接続する。
