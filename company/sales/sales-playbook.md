## 1. ファネル定義とKPI

```
リード (100社リスト) → コンタクト → 初回商談 (Discovery) → Assessment受注
→ Sprint受注 → 保守契約
```

| ステージ | 定義 | M1-3の目標転換率 |
|---|---|---|
| リード | ICP合致 + 連絡先特定 | 100社 |
| コンタクト | 返信 or 会話が発生 | 30% |
| 初回商談 | 30分以上の会話実施 | 10社 (M1) |
| Assessment受注 | $3,000の支払い | 商談の30% |
| Sprint受注 | Assessment実施企業の | 50-70% |
| 保守契約 | Sprint納品企業の | 70%以上 |

## 2. 営業の中心原則: 数字で話す

抽象的なAIの話をしない。すべての会話をこの6問に収束させる:

1. その業務は **現在何分/何時間** かかっていますか
2. **月に何回** 行われますか
3. **誰が** (何人が・時給いくらの人が) 実行していますか
4. **エラー** はどのくらい発生し、1件いくらの損失ですか
5. 自動化すると **月何時間** 削減できますか
6. 投資は **何ヶ月で回収** できますか

この6問に答えられた瞬間、商談は「AIに興味ありますか」から
「月$2,000の損失を$15,000で止めますか」に変わる。

## 3. リード獲得チャネル (優先順)

1. **紹介** (最優先・成約率最高): 前職人脈・商工会議所・既存顧客からの紹介依頼を仕組み化
2. **LinkedIn**: ICP検索 → コネクト → 価値提供メッセージ (売り込みは3通目以降)
3. **コールドメール**: 業界×業務特化の具体例を1つ入れる (「御社と同業のA社では…」)
4. **コンテンツ**: 自動化事例の記事・LinkedIn投稿 (週1) → インバウンドの種
5. **イベント**: 日系商工会議所・ASUG・Zendeskユーザー会

## 4. Discovery Call の型 (30分)

```
0-5分   ラポール + アジェンダ合意
5-15分  業務の深掘り (§2の6問を自然に埋める)
         「先月、チームが一番時間を取られた定型作業は何でしたか?」
15-20分  現状の構造整理を声に出して確認 (「つまり毎月X時間をYさんが…」)
20-25分  進め方の提示: Assessment ($3,000/5日) → Sprint (14日) の2段階
         「まず$3,000で対象選定とROI試算をやります。Sprint受注なら全額充当します」
25-30分  次のアクション確定 (Assessment日程 or 追加情報の期日)
```

失格判定 (その場で見極める): 対象業務が特定できない / 決裁ルートが不明 /
データアクセス不可 → 深追いせず「業務が特定できたらまた」で終了。

## 5. クロージングの原則

- クローズするのは常に**次の小さなコミット** (契約書ではなく「Assessment開始日」)
- 提案書は3営業日以内に送る。鮮度が成約率
- 無料作業をしない。「軽く作ってみてよ」→「それがまさにSprintです。Assessmentから始めましょう」
