# SAP GUIスクリプティング (VBS) × Power Automate Desktop 自動化カタログ

標準取引コード別に「バックオフィス業務の自動化につながるもの」を FI (会計) /
SD (販売) / MM (購買・在庫) で整理した提案。実装は `sapgui-vbs/` を参照。

## 実行アーキテクチャ

```
Power Automate Desktop (アテンド型 / Bot用VM)
  │ フロー変数 (取引コード別のインプット)
  │ 「VBScriptの実行」または cscript.exe //Nologo <script>.vbs /名前付き引数
  ▼
VBS (SAP GUI Scripting API)
  ├─ 既存ログオン済みSAP GUIセッションにアタッチ (資格情報は持たない)
  ├─ 画面項目へ変数を設定 → 実行/保存
  ├─ ステータスバーから伝票番号/受注番号を取得
  ├─ 照会画面での読み戻し検証 (FB03等)
  └─ 終了コード + 結果ファイル (Key=Value) を返す
  ▼
PADが終了コードで分岐 → 台帳記録 (SharePoint) / Teams通知 / 例外キュー
```

前提設定:
- サーバ側: `RZ11` で `sapgui/user_scripting = TRUE`
- クライアント側: SAP GUIオプション → アクセシビリティ&スクリプト → スクリプト有効化
- **画面項目ID (`wnd[0]/usr/...`) はSAPバージョン・画面バリアントで変わる。**
  必ず対象環境で Script Recording and Playback (Alt+F12) を使って記録し、
  雛形のIDを差し替えてから使うこと

## 終了コード契約 (PAD分岐用)

| code | 意味 | PADのアクション |
|---|---|---|
| 0 | 成功 (伝票番号は結果ファイル) | 台帳記録 → 完了通知 |
| 1 | 入力値の検証エラー (SAP未接触) | 依頼元へ差し戻し |
| 2 | SAPエラー (ステータスバー E/A) | エラーメッセージ添付で例外キューへ |
| 3 | セッション接続不可 | Bot VMヘルスチェック → ops通知 |
| 4 | 転記成功だが読み戻し検証NG | **最優先で有人確認** (要調査) |

| FB70 | 得意先請求書入力 | 会社コード, 得意先, 日付, 金額, 税コード, 収益勘定 | L2 | FB60の売上版。同じ雛形で横展開可 |
| FB50 | GL仕訳入力 | 会社コード, 日付, 借方/貸方明細CSV (勘定, 金額, 原価センタ) | L2 | 経費振替・月次定型仕訳。明細はCSVで複数行 |

## 導入順の提案 (効果 × 安定性)

```
第1段: L0参照系で運用を確立 (壊れても業務影響ゼロ)
   FBL1N / FBL5N / ME2N / MB52 / VA05 → 定例レポートのPADスケジュール実行

第2段: 件数の多いL2転記を「全件PAD承認付き」で
   FB60 (PO無し請求書) → MIRO (PO有り請求書) → VA01 (受注転記)

第3段: マスタ系L1と周辺
   FK02 / VD02 / ME51N / FB50定型仕訳

常に人間に残すもの:
   F110の支払実行 / ME29N発注承認 / 高額・イレギュラー案件の判断
```

## ガードレール (VBS/PAD層での実装)

1. **資格情報を持たない**: VBSはログオン済みセッションにアタッチするのみ。
   Bot用SAPユーザは取引コード単位の最小権限ロール
2. **入力検証をSAP接触前に**: 金額・日付・コード体系はVBS冒頭で検証 (exit 1)
3. **読み戻し検証**: 転記系は保存後にFB03等で伝票を開き直して確認 (NG時 exit 4)
4. **ステータスバー全記録**: 全ステップをログファイルに記録し台帳へ添付
5. **重複防止**: PAD側で冪等キー (仕入先+請求書番号) を台帳と突合してから起動
6. **ドライラン**: `/DryRun:1` で画面入力まで行い保存せず中断 (新シナリオの試験用)
